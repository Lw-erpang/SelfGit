## 1. 产品概述与范围

### 1.1 一句话定位
面向个人开发者的 Android 端"私有 Gitea 应用商店"：登录自托管的 Gitea 实例，浏览全量仓库、安装/更新 APK、从手机上传 APK 并维护每个应用的历史版本库。**本项目需配合自建 Gitea 使用，自身不提供服务端。**

### 1.2 范围内（已实现）
- 连接**单个**自托管 Gitea 实例；多地址仅作冗余切换（主备），不支持多实例同时在线
- 登录：密码引导 + 令牌运行（混合模式）；2FA 账号自动降级为粘贴令牌
- 主备地址：局域网 HTTP（主）+ HTTPS/HTTP（备），独立编辑与独立连通性探测
- 仓库全量列表、Release 列表、Markdown 渲染、APK 下载与安装
- 追踪角标：最新 Release 与本机已装版本对比；**外部安装的应用**通过仓库根目录 `app.json` 约定识别
- 手机上传 APK：SAF 选择 / 从已装应用提取 base.apk / 接收系统分享；自动建库（一应用一库为默认）、tag 查重、上传记录、可取消
- 下载完成后同步到公共目录 `Download/SelfGit/`（文件管理器可见）
- 安装后端四种：系统安装器 / Shizuku 静默安装 / Root 静默安装（libsu）/ 第三方安装器
- 启动时刷新 + 前台手动刷新；**不做任何后台同步**

### 1.3 范围外（明确不做）
- 后台定时轮询、推送通知、Webhook 接收
- GitHub / GitLab / Codeberg 等任何其他 Forge
- 断点续传上传
- 多账号同时登录、组织/团队权限管理界面
- 公开发布/应用市场功能（发现、热门、评分）

## 2. 总体架构

- **形态**：单机 Android App，无自有服务端，直连 Gitea REST API（`/api/v1`）。
- **技术栈**（当前实现）：Kotlin 2.2.10 + Jetpack Compose + OkHttp 4.12 + Android Keystore + Shizuku 13（UserService）+ libsu 6.0；本地持久化用 SharedPreferences + `org.json`（未引入 Room / Retrofit）。
- **模块划分**（`app/src/main/java/com/selfgit/app/`）：
  1. `net/`：GiteaClient（API 封装与令牌注入）、InstallRouter（安装后端路由）、ApkInstaller（解析/校验）
  2. `data/`：SettingsStore（主机与偏好）、TrackingStore（仓库↔包名映射）、PinnedStore（置顶）、UploadHistoryStore（上传记录）
  3. `shell/`：Shizuku UserService（AIDL）执行 shell 命令
  4. `ui/`：五个页面 + 玻璃组件体系（详见 UI 设计文档）

## 3. 登录与运行机制（核心）：密码引导 + 令牌运行

### 3.1 模式总览

| 阶段 | 凭证 | 传输方式 | 说明 |
|---|---|---|---|
| 引导期（一次性） | 账号密码 | HTTP Basic Auth，仅用于调用"创建令牌"接口 | 密码**不落盘**，用完即弃 |
| 运行期（常态） | 访问令牌 | 请求头注入（`Authorization: token …`） | Keystore AES/GCM 加密存储，可吊销 |

### 3.2 首次登录流程

1. 填写主地址（含可选备地址）→ 免认证探测（GET `/api/v1/version`，5 秒超时）验证可达；主备**各自独立探测**，任一可达即可进入登录。
2. 认证二选一：
   - **密码引导**：Basic Auth 调用创建令牌接口，自动创建两个令牌：
     - `selfgit-ro-{时间戳}`：`read:repository, read:user`（浏览/下载）
     - `selfgit-rw-{时间戳}`：`read:repository, write:repository, write:user, read:user`（上传；**`write:user` 为新建仓库 API 必需**）
   - **直接粘贴令牌**：用户在网页端自建令牌后粘贴，App 校验有效性。
3. 创建成功 → 令牌加密落盘 → 立即清除内存中的密码 → 用 ro 令牌自校验（GET `/api/v1/user`）→ 进入主界面。
4. 令牌重名时自动追加随机后缀重试一次。

### 3.3 令牌使用规则

- 浏览类请求固定用 ro 令牌；上传类请求切换为 rw 令牌。
- 令牌 Keystore 加密，随 App 卸载销毁；清除全部数据需输入「确认清除」二次确认。

### 3.4 令牌失效处理

| 信号 | 判定 | App 行为 |
|---|---|---|
| HTTP 401 | 令牌过期/吊销/账号变更 | **保留全部配置与本地缓存**，进入重新认证页（可返回设置取消）；支持密码引导重建或粘贴新令牌 |
| HTTP 403（浏览） | ro 令牌权限被改窄 | 明确提示所需权限与补救路径 |
| HTTP 403（上传，缺 `write:user`） | rw 令牌 scope 不足 | 提示重新认证以重建含 `write:user` 的 rw 令牌 |

明确不做：不自动重建令牌（避免重试风暴）；不静默清除本地数据；不在失效时自动切换账号。

### 3.5 登录边界条件

- **2FA 已开启**：Basic Auth 直连 API 被拒 → 提示改用粘贴令牌。
- **网络中途断开**：任一步骤失败允许重试；令牌已创建但自校验失败时提示到网页端检查，避免重复创建。

## 4. 仓库地址主备配置

### 4.1 配置结构

- **主地址**：局域网场景，如 `http://192.168.x.x:3000`
- **备地址**：公网场景，如 `https://gitea.example.com`
- 两地址必须指向**同一 Gitea 实例**；App 不做数据一致性校验，由用户保证。

### 4.2 独立编辑与探测（当前实现）

- 主地址与备地址在设置页各有**独立编辑入口**，共用统一编辑弹窗。
- 保存前**自动探测该地址连通性**：仅可达地址落盘；探测失败提示"该地址当前不可达，未保存"，不覆盖现有配置。
- 备地址留空 = 清除（免探测）；主地址必填。
- 登录时的保存同样遵循"只有探测通过的地址落盘"，**绝不把备地址回填为主地址**（修复早期"仅备可达时主地址被覆盖"的问题）。

### 4.3 地址选择策略

1. **记忆优先**：优先使用"最后成功地址"（持久化）。
2. **自动探测**：记忆地址失败时按 主 → 备 顺序探测（免认证 GET `/api/v1/version`，超时 5 秒）；空白主地址自动跳过。
3. **切换判定**：仅连接类失败（超时、DNS、不可达、TLS）触发备地址切换；**认证失败不触发切换**。
4. **会话内粘滞**：一次会话内探测成功后不再来回切换。

### 4.4 HTTPS 边界

- 仅接受**系统信任的证书**（如 Let's Encrypt）；自签证书不支持。
- 主备地址协议可以不同（主 http、备 https）；按配置原样连接，不做自动升级。
- 网络安全配置全局放行明文 HTTP（自托管内网场景的显式取舍）。

## 5. 数据刷新机制（无后台同步）

### 5.1 原则

- **无 WorkManager / 无轮询 / 无推送**；数据新鲜度完全由"使用时"驱动。
- 无网或主机不可达时展示已有数据，失败原因 Toast 提示。

### 5.2 刷新触发

- **启动刷新**：进入前台且距上次成功刷新超过防抖阈值（60 秒）；仓库列表为空时强制刷新（避免进程重启后白列表）。
- **手动刷新**：刷新按钮；上传成功后自动全局刷新。
- 刷新管线并行拉取：仓库列表 + 各仓库最新 Release tag + 各仓库 `app.json` 元数据。

### 5.3 生命周期边界

| 场景 | 行为 |
|---|---|
| 刷新中退出 App | 请求继续完成，下次启动读结果 |
| 刷新中主机不可达 | 静默失败，保留现有数据 + Toast 提示 |
| 多地址配置 | 仅刷新当前生效地址对应实例 |

## 6. 安装与追踪

### 6.1 追踪与更新角标

- **映射来源**（按优先级）：本机下载安装记录（TrackingStore）→ 仓库根目录 `app.json` 的 `packageName` 字段（覆盖外部安装的应用）。
- 实际已装版本实时查 PackageManager；Android 11+ 包可见性通过 `QUERY_ALL_PACKAGES` 声明（自分发应用，无商店合规限制；部分 ROM 需用户在系统设置中额外授予「获取应用列表」权限，列表为空时 UI 给出引导）。
- 角标规则：已装且 = 最新 → 「已是最新」（绿）；已装且 < 最新 → 「有更新 vX.Y.Z」（橙）；映射存在但未安装 → 无角标。
- 版本比较：从 tag / 版本串提取数字版本逐段比较（覆盖 `v1.9.4`、`应用名-v1.0` 两种 tag 形态）。

### 6.2 下载

- 附件**两段式下载**：先取附件元数据的 `browser_download_url`（`/attachments/{uuid}`）再流式落盘；实时百分比进度；失败自动清理半成品并显示重试。
- 下载目标为 App 专属外部目录（免存储权限）；非 APK 附件标记"不可安装"。
- 下载完成后同步复制一份到公共目录 **`Download/SelfGit/`**（MediaStore，API 29+，同名覆盖），文件管理器可见。

### 6.3 安装四后端（InstallRouter）

| 后端 | 机制 | 未就绪行为 |
|---|---|---|
| 系统安装器 | FileProvider + ACTION_INSTALL_PACKAGE | —（默认兜底） |
| Shizuku | UserService（AIDL）绑定 shell uid 服务执行 `pm install -r` | 未运行/未授权时提示并回退系统 |
| Root | libsu `Shell.cmd("pm install -r …")` | 无 su 时提示并回退系统 |
| 第三方安装器 | 枚举可处理安装意图的应用（安装 action / APK mime / `content://` scheme 三类探测）+ **接管型安装器白名单**（LSPosed 安装接管模块无安装 filter，选中后走系统安装器由其接管） | 被卸载时自动回退系统并提示 |

### 6.4 安装前校验

- 目标 APK 安装证书 SHA-256 与本机已装版本比对：不一致 → 弹窗警示（需先卸载）。
- 降级检测：目标版本低于已装版本 → 弹窗警示。

## 7. 上传发布（手机端直传）

### 7.1 取得 APK 的三种方式

1. SAF 选择 APK 文件
2. **从已装应用选择**：列出本机应用（搜索 / 含系统应用开关），提取其 base.apk（Split APK 应用仅含基础包，给出提示）
3. **系统分享接收**：在其他应用分享 APK 时选择 SelfGit，自动跳转上传页并装载解析

### 7.2 上传流程（P4）

1. 解析：应用名、包名、versionName、versionCode、架构（遍历 `lib/<abi>/`）、大小。
2. **归属**：
   - `新建仓库`（默认，一应用一库）：仓库名由应用名清洗推导；`auto_init=true` 自动生成 README；默认私有；409（已存在）提示改名或改模式
   - `已有仓库`：默认按包名匹配追踪映射自动选中，可手动改选
3. tag 模板 `{应用名}-v{版本}`；700ms 防抖查重，冲突红字提示并禁用上传（**不覆盖远端 tag**）。
4. 建 Release：描述 = 修改日志（模板预填可编辑）+ 固定元数据（包名 / versionCode / 架构）。
5. 上传附件：multipart + 进度展示，失败自动重试 ≤ 2 次；**上传中可取消**（中断网络请求，不写失败记录）。
6. **失败清理**：Release 已建但附件最终失败 → 弹窗选择"删除空 Release"（默认）或"保留待手动补传"。
7. 成功后异步补写仓库 `app.json`（已存在跳过、失败静默，不干扰上传结果），并触发全局刷新。

### 7.3 上传记录

最近 30 条本地留存（成功 / 重试耗尽 / Release 创建失败均记录）；上传页展示最近 10 条，可清空。

## 8. 仓库约定文件

| 文件 | 作用 |
|---|---|
| `app.json` | 仓库根目录 `{"packageName": "...", "displayName": "..."}`，用于外部安装应用的更新检测（上传时自动补写） |
| `icon.png`（或 jpg/jpeg/webp） | 仓库根目录应用图标（本机未装时详情页显示） |
| `README.md` | 仓库详情页「应用详情」板块渲染 |

tag 规范：项目仓库 `vX.Y.Z`；杂项应用集合仓库 `应用名-vX.Y.Z`。APK 只挂 Release 附件，不进 git 历史；修改日志写在 Release 正文。

## 9. 异常处理矩阵

| 错误类别 | 典型场景 | 用户提示 | 系统行为 |
|---|---|---|---|
| 连接失败 | 超时/DNS 失败/拒绝连接 | "主机不可达，已尝试备地址" | 触发主备切换；保留现有数据 |
| TLS 失败 | 自签证书/域名不匹配 | "证书不受信任：仅支持系统信任证书" | 终止，不回退明文 |
| 认证失败 401 | 令牌过期/吊销 | "登录已失效，请重新认证" | 进重新认证页，保留配置与缓存 |
| 权限不足 403 | scope 被改窄 / rw 缺 `write:user` | 指明缺失权限与补救路径 | 按操作类型终止 |
| 上传中断 | 网络切换/信号弱 | "上传失败（已重试 2 次）" | 按失败清理策略处理 |
| 解析失败 | 非 APK 文件 | "无法读取应用信息：可能不是标准 APK" | 终止上传 |
| 服务器错误 5xx | Gitea 重启 | "服务端暂时不可用" | 提示重试，不切地址 |
| 版本冲突 | tag 已存在 | "版本已存在，不可覆盖" | 终止，建议改版本号 |
| 应用列表为空 | ROM 隐私权限拦截 | 引导授予「获取应用列表」权限 | 已装应用选择弹窗内提示 |

## 10. 安全与隐私说明

- **令牌**：Keystore AES/GCM 加密、ro/rw 分级、可在 Gitea 网页端随时吊销。
- **密码**：仅存在于引导请求的内存与传输层，不持久化、不写日志。
- **HTTP 明文（主地址）**：令牌与 APK 走明文传输，风险与浏览器直连内网方案相同；备地址建议启用 HTTPS。此为用户已知悉的显式取舍。
- **应用列表**：`QUERY_ALL_PACKAGES` 仅用于本机已装版本检测，不上传任何列表数据。
- **无遥测**：App 不收集、不上报任何数据；崩溃日志仅本地留存。
